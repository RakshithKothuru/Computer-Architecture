## 1. Interrupts and Their Types

An **interrupt** is an event that temporarily stops normal program execution and transfers control to an **Interrupt Service Routine (ISR)**.

After servicing the interrupt, the CPU restores its previous state and resumes execution.

```text
Program execution
       ↓
Interrupt occurs
       ↓
CPU saves PC and state
       ↓
ISR executes
       ↓
CPU restores state
       ↓
Program resumes
```

### Hardware Interrupt

Generated by an external hardware device.

Examples:

- Timer expiration
- Keyboard input
- Network packet arrival
- DMA transfer completion

Hardware interrupts are generally **asynchronous** because they are independent of the currently executing instruction.

### Software Interrupt

Generated intentionally by executing a special instruction.

It is commonly used for:

- System calls
- Requesting operating-system services
- Debugging

Software interrupts are **synchronous** because they are caused by an executed instruction.

### Exception

Generated internally by the CPU when it detects a condition while executing an instruction.

Examples:

- Divide by zero
- Illegal instruction
- Page fault
- Arithmetic overflow

Exceptions are **synchronous** because they are associated with a particular instruction.

| Type | Generated By | Nature | Example |
|---|---|---|---|
| Hardware interrupt | External device | Asynchronous | Timer or I/O completion |
| Software interrupt | Special instruction | Synchronous | System call |
| Exception | CPU during instruction execution | Synchronous | Page fault |

### Basic Handling Process

1. CPU completes or stops the current instruction, depending on the event.
2. It saves the PC and required execution state.
3. It jumps to the corresponding handler.
4. The handler services the event.
5. The saved state is restored.
6. Program execution resumes.

## 2. Maskable vs Non-Maskable Interrupts

### Maskable Interrupt

A maskable interrupt can be temporarily disabled by the CPU.

It is used for regular events such as:

- Timer interrupts
- Keyboard input
- Network activity
- I/O completion

### Non-Maskable Interrupt

A **Non-Maskable Interrupt (NMI)** cannot normally be disabled using regular interrupt-masking instructions.

It is used for critical events such as:

- Hardware failure
- Memory error
- Power-failure warning
- Watchdog timeout

| Maskable Interrupt | Non-Maskable Interrupt |
|---|---|
| Can be disabled | Normally cannot be disabled |
| Used for regular events | Used for critical events |
| May wait for servicing | Requires immediate attention |
| May have different priorities | Usually has very high priority |

## 3. Polling vs Interrupt-Driven I/O

### Polling

In polling, the CPU repeatedly checks the device status register to determine whether the device is ready.

```text
while (device_not_ready)
    check_device_status;
```

**Advantages:**

- Simple to implement
- Useful when the waiting time is short

**Disadvantages:**

- Wastes CPU cycles
- Inefficient for slow devices

### Interrupt-Driven I/O

The CPU starts the I/O operation and continues executing other instructions. When the device requires attention, it generates an interrupt.

**Advantages:**

- CPU does not continuously wait
- Efficient for slow or irregular devices

**Disadvantages:**

- Interrupt handling introduces overhead
- Frequent interrupts can reduce performance

| Polling | Interrupt-Driven I/O |
|---|---|
| CPU repeatedly checks the device | Device notifies the CPU |
| CPU wastes time while waiting | CPU can perform other work |
| Simple implementation | Requires interrupt hardware |
| Suitable for short waits | Suitable for irregular events |

> In both techniques, the CPU still transfers the actual data. DMA can remove the CPU from this repetitive transfer work.

## 4. I/O Addressing Methods

I/O devices can be accessed using:

1. **Memory-Mapped I/O**
2. **Isolated I/O or Port-Mapped I/O**

### Memory-Mapped I/O

In **memory-mapped I/O**, device registers and main memory share the same address space.

The CPU accesses device registers using ordinary load and store instructions.

```text
Single address space

0x0000_0000 ─┐
              │ Main memory
0x3FFF_FFFF ─┘

0x4000_0000 ─┐
              │ I/O device registers
0x4000_FFFF ─┘
```

#### Example

Assume that a UART has the following registers:

```text
0x4000_0000 → Data register
0x4000_0004 → Status register
0x4000_0008 → Control register
```

The CPU accesses these registers using normal memory instructions.

#### Advantages

- No separate I/O instructions are required
- Normal load/store instructions and addressing modes can be used
- Programming is simpler

#### Disadvantages

- I/O registers occupy part of the memory address space
- Device-register locations should generally not be cached

> In C, memory-mapped device registers are generally accessed using `volatile` so that the compiler does not remove or incorrectly optimize the accesses.

---

### Isolated I/O or Port-Mapped I/O

In **isolated I/O**, memory and I/O devices have separate address spaces.

```text
Memory Address Space       I/O Address Space
--------------------       -----------------
Main memory                Device ports
```

The processor uses special I/O instructions to access device ports.

For example, x86 provides:

```text
IN  → Read from an I/O port
OUT → Write to an I/O port
```

#### Advantages

- I/O devices do not occupy memory address space
- Memory and I/O operations are clearly separated

#### Disadvantages

- Requires special I/O instructions
- Usually provides fewer addressing modes

### Memory-Mapped I/O vs Isolated I/O

| Feature | Memory-Mapped I/O | Isolated I/O |
|---|---|---|
| Address space | Shared with memory | Separate I/O address space |
| Instructions | Normal load/store | Special instructions such as `IN` and `OUT` |
| Addressing modes | Normal memory addressing modes | Usually limited |
| Memory address space | Part is used for I/O | Entire space remains available |
| Programming | Simpler and more flexible | Less flexible |
| Common usage | ARM, RISC-V and modern systems | Traditionally associated with x86 |

> The main difference is whether device registers share the memory address space or use a separate I/O address space.

# 5. Direct Memory Access (DMA)

## 5.1 What is DMA?

**Direct Memory Access (DMA)** allows data to be transferred directly between an I/O device and main memory without the CPU executing an instruction for every byte or word.

A hardware unit called the **DMA controller** manages the transfer.

```text
Without DMA:

I/O Device → CPU → Main Memory


With DMA:

I/O Device ↔ DMA Controller ↔ Main Memory
                   ↑
          CPU only configures it
```

The CPU initializes the DMA operation and is usually interrupted after the complete block has been transferred.

---

## 5.2 Why is DMA Needed?

Consider transferring a 4 KB block from a storage device to memory.

### Without DMA

For every byte or word, the CPU must:

1. Check whether the device is ready.
2. Read data from the device register.
3. Write the data into memory.
4. Repeat until the entire block is transferred.

This consumes a large number of CPU cycles.

### With DMA

The CPU provides the DMA controller with:

- Source address
- Destination address
- Transfer size
- Transfer direction
- Transfer configuration

The DMA controller then transfers the complete block independently. Meanwhile, the CPU can execute other instructions.

DMA is useful for high-volume devices such as:

- SSDs and storage controllers
- Network interfaces
- Audio and video devices
- GPUs and hardware accelerators
- ADCs and data-acquisition systems

---

## 5.3 DMA Controller Registers

A DMA controller commonly contains the following registers.

### Source Address Register

Stores the address from which data must be read.

The source can be:

- A memory location
- An I/O device data register

### Destination Address Register

Stores the address to which data must be written.

The destination can be:

- A memory location
- An I/O device data register

### Transfer Count Register

Stores the number of bytes, words or transfer units remaining.

The count is decremented after every transfer.

### Control Register

Specifies parameters such as:

- Transfer direction
- Data width
- Transfer mode
- Source address increment
- Destination address increment
- Interrupt enable

### Status Register

Indicates:

- Transfer completion
- DMA activity
- Transfer errors
- Remaining transfer state

---

## 5.4 DMA Transfer Process

### Step 1: CPU Configures DMA

The CPU programs the DMA controller with the required information.

For a device-to-memory transfer:

```text
Source address      = Device data-register address
Destination address = Starting memory address
Transfer count      = Number of bytes or words
Direction           = Device to memory
```

The CPU then enables the DMA channel.

### Step 2: Device Requests DMA

When the device is ready to send or receive data, it sends a **DMA request** to the DMA controller.

### Step 3: DMA Requests Bus Access

The DMA controller requests permission to use the memory or system bus.

Since the CPU and DMA controller may share the bus, an arbitration mechanism determines which one receives control.

### Step 4: DMA Becomes Bus Master

The CPU completes its current bus transaction and grants the bus to the DMA controller.

The DMA controller temporarily becomes the **bus master**, meaning it can generate:

- Addresses
- Read commands
- Write commands

### Step 5: Data Is Transferred

For a device-to-memory transfer, the DMA controller:

1. Reads data from the device.
2. Writes the data into memory.
3. Increments the memory address.
4. Decrements the transfer count.

```text
Memory address = Memory address + Transfer size
Transfer count = Transfer count - 1
```

This process continues until the transfer count reaches zero.

### Step 6: Transfer Completion

After transferring the complete block, the DMA controller:

- Updates its status register
- Releases the bus
- Usually generates an interrupt

The CPU then executes the DMA-completion interrupt handler.

### Overall Flow

```text
CPU configures DMA
        ↓
Device sends DMA request
        ↓
DMA controller requests the bus
        ↓
DMA controller becomes bus master
        ↓
Data is transferred between device and memory
        ↓
Transfer count reaches zero
        ↓
DMA controller interrupts the CPU
```

---

## 5.5 Example of DMA Operation

Suppose a device must transfer four words into memory starting at address `1000`.

Initial configuration:

```text
Destination address = 1000
Transfer count      = 4
Word size           = 4 bytes
```

| Transfer | Memory Address | Count After Transfer |
|---:|---:|---:|
| Word 1 | 1000 | 3 |
| Word 2 | 1004 | 2 |
| Word 3 | 1008 | 1 |
| Word 4 | 1012 | 0 |

Since each word is four bytes, the destination address increases by four after every transfer.

When the count reaches zero, the DMA controller generates a completion interrupt.

---

## 5.6 DMA Transfer Directions

DMA supports the following transfer directions:

- **Device to memory:** Used for receiving data, such as reading from storage.
- **Memory to device:** Used for sending data, such as transmitting a network packet.
- **Memory to memory:** Used to copy data between two memory regions.

---

## 5.7 DMA Transfer Modes

### Burst Mode

In burst mode, the DMA controller takes control of the bus and transfers the complete block continuously.

```text
CPU uses bus → DMA transfers complete block → CPU regains bus
```

#### Advantages

- Highest transfer rate
- Low bus-arbitration overhead

#### Disadvantages

- CPU may be unable to access memory for a significant duration
- Long DMA bursts can increase CPU memory-access latency

---

### Cycle-Stealing Mode

In cycle-stealing mode, the DMA controller transfers one word or a small unit at a time by taking individual bus cycles.

```text
CPU bus cycle → DMA bus cycle → CPU bus cycle → DMA bus cycle
```

The CPU is not stopped for the complete transfer, but its memory accesses become slower.

#### Advantages

- CPU and DMA both continue to make progress
- DMA does not hold the bus for a long duration

#### Disadvantages

- DMA transfer is slower than burst mode
- CPU performance decreases because some bus cycles are stolen

---

### Transparent Mode

In transparent mode, the DMA controller transfers data only when the CPU is not using the bus, causing minimal CPU interference but resulting in a slower and unpredictable transfer time.

---

## 5.8 Address Increment and Fixed Address

During DMA, not every address is necessarily incremented.

### Device-to-Memory Transfer

```text
Source address      = Fixed
Destination address = Incremented
```

The device data register remains at the same address, while successive data items are stored in different memory locations.

### Memory-to-Device Transfer

```text
Source address      = Incremented
Destination address = Fixed
```

Successive memory locations are read, but all data is written to the same device data register.

### Memory-to-Memory Transfer

```text
Source address      = Incremented
Destination address = Incremented
```

Both addresses are incremented as the data is copied.

---

## 5.9 DMA and Interrupts

DMA and interrupts perform different jobs:

- **DMA transfers the actual data.**
- **Interrupt informs the CPU about an event.**

A typical operation is:

```text
CPU configures DMA
        ↓
DMA transfers the complete block
        ↓
DMA interrupts the CPU after completion
```

Without DMA, the CPU may require an interrupt for every small unit of data. With DMA, one interrupt may be sufficient for an entire block.

---

## 5.10 DMA and Cache Coherence

DMA usually accesses main memory directly, while the CPU may access the same data through its cache.

This can produce inconsistent values.

### Case 1: DMA Reads from Memory

Suppose the CPU modifies data in a write-back cache, but the updated value has not yet reached main memory.

```text
CPU cache   → New data
Main memory → Old data
```

If DMA reads main memory, it may transfer the old data.

**Solution:** Flush or clean the relevant cache lines before starting DMA.

### Case 2: DMA Writes to Memory

Suppose DMA writes new data into main memory, but the CPU cache still contains an older copy.

```text
Main memory → New DMA data
CPU cache   → Old data
```

The CPU may continue reading stale cached data.

**Solution:** Invalidate the relevant cache lines before the CPU reads the DMA result.

Modern systems may support **cache-coherent DMA**, where hardware maintains consistency automatically.

---

## 5.11 Advantages of DMA

- Reduces CPU involvement
- Transfers large blocks efficiently
- Improves overall system performance
- Supports high-speed I/O devices
- Allows CPU computation and I/O transfer to overlap
- Reduces the number of interrupts

## 5.12 Limitations of DMA

- DMA and the CPU compete for memory bandwidth.
- Cache coherence must be handled correctly.
- DMA setup overhead makes it inefficient for very small transfers.

---

## 6. Comparison of I/O Techniques

| Feature | Polling | Interrupt-Driven I/O | DMA |
|---|---|---|---|
| Device readiness detected by | CPU repeatedly checking | Device interrupt | DMA request |
| Actual data transferred by | CPU | CPU | DMA controller |
| CPU involvement | Very high | Moderate | Low |
| CPU can work during waiting period | No | Yes | Yes |
| Suitable for | Small or simple transfers | Occasional transfers | Large block transfers |
| Hardware complexity | Low | Medium | High |
| Overall performance | Low | Medium | High |

## Final Understanding

```text
Polling:
CPU waits and transfers the data.

Interrupt-driven I/O:
CPU performs other work but transfers the data when interrupted.

DMA:
CPU configures the operation, and the DMA controller transfers the data.
```

The main purpose of DMA is not to eliminate the CPU completely. The CPU is still responsible for:

1. Configuring the DMA controller
2. Providing source and destination addresses
3. Providing the transfer size
4. Handling cache consistency when necessary
5. Processing the completion interrupt

DMA removes the CPU from the repetitive work of transferring every byte or word.
